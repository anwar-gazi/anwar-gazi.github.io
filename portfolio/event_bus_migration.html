The Coupling Problem

Prior to this migration, the application relied on a pattern of Prop Drilling to handle task navigation. The functionality to "Open a Task" was passed down from the root layout through multiple intermediate layers (`Board` → `Column` → `TaskCard`).

This created rigid coupling: leaf components like `TaskCard` could not function without being explicitly wired by their parents, making refactoring difficult and new features (like global command palettes) hard to integrate.

The Solution: Event Bus

We implemented a lightweight, type-safe Event Bus (Singleton) services. This decoupled the producers (components that want to open a task) from the consumers (components that need to react, like the URL router or the Task Pane UI). 

// src/services/client/TaskEventBus.ts
type TaskEvents = {
  "open": (taskId: string) => void;
  "close": () => void;
};

export const taskEventBus = new TaskEventBus();

Orchestration & Data Flow

A critical requirement was maintaining URL Synchronization (Deep Linking). The Event Bus acts as the central hub, notifying the routing hook (`useBoardRouting`) to update the URL as a side effect, while simultaneously telling the UI to render the pane.

Refactoring Impact

The refactoring touched GlobalTaskSearch, CommandPalette, and RunningTasksBar, removing redundant logic and unifying behavior.

Before: Prop Drilling

  • Parent must pass callbacks
  • Nested components depend on props
  • Refactoring requires touching entire tree
  • Hard to trigger from outside components

After: Event Bus

  • Zero dependencies on parent
  • Import and emit anywhere
  • Type-safe event payloads
  • Single source of truth for navigation
