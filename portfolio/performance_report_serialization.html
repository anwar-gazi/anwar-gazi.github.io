Performance Architecture

Technical analysis of Elimination of Double Serialization and Reference Equality optimizations.

1. Eliminated "Double Serialization" Impact: Critical

The most significant performance bottleneck identified was a redundant data transformation pipeline. The API routes performed an expensive, redundant loop over the data set, essentially processing every entity twice before response generation.

Before

For a board with 100 tasks, the server iterated over hundreds of objects multiple times, allocating new memory and deeply copying values just to produce the exact same result structure twice.

After

We deleted the entire middle layer of processing. Data is fetched, transformed once in the Repository, and streamed directly to the response.

2. JSON Serialization Speed Impact: Latency (TTFB)

Replacing native Date objects with ISO Strings fundamentally changes how the V8 engine and Next.js handle serialization, resulting in reduced CPU overhead on the server.

Using Date Objects

JSON.stringify must invoke .toJSON() on every Date instance. This function call overhead scales linearly with the number of date fields (created, updated, due, closed) across thousands of entities.

[Object].toJSON() call × 5000 fields
Using ISO Strings

Strings are primitives. JSON.stringify handles them natively by simply copying memory buffers. This is one of the fastest operations in V8.
